# The Ask docks at the bottom of the middle column — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Spec:** `docs/specs/2026-09-16-ask-dock.md`. It changes `docs/specs/2026-09-15-one-ask-scoped.md`
(shipped as #311) in one place only — **where the Ask lives and how a topic reaches it**. The request
contract, the chips-from-`applied_scope` rule and the scope copy are unchanged.

**Branch:** `feat/ask-dock`, based on `dev` `c5e0882`. Another process may commit in this worktree
concurrently: **re-read every line number and every `?v=` before editing it.**

**Goal:** the Ask is a bar pinned to the bottom of the middle column, outside the scrolling content.
Its scope follows the selection. Asking opens a conversation overlay upward, over the list, without
moving the list. `Ask about this topic`, `pinTopicAsk` and the focus-nonce scroll are deleted.

**Tech:** vanilla JS IIFEs + `React.createElement`, no build step. Tests: `node --test tests/*.test.js`
(Node v24.13.1, no package.json).

## Controller rulings (2026-09-16)

1. **Non-day states.** The dock renders nothing when the resolved context has no `date` — the project
   picker, first paint and the admin available-users disambiguation. The "no report for this day" state
   keeps a day-scoped dock. (Plan ambiguity 2, decided by the controller; a bar with nothing to narrow to
   would read as a global Ask and mislead.)
2. **Site view.** Task 6 ships by default (spec §2.1); the user may veto it, and the veto is "skip Task 6",
   not "undo" anything.
3. **Meeting-topic divider.** Accepted as described in ambiguity 4: selecting a topic with no
   `topic_row_id` maps to the day context and the divider reads "Now asking about the whole day".
4. **Suggestions rule.** `msgs.length === 0 && focused` in dock mode — focus narrows the shipped rule and
   never widens it (ambiguity 5).

## The three risky seams

Each of these regresses **silently** — nothing throws, every test can still pass.

1. **The Footer must render OUTSIDE the scrolling content.** `MiddleColumn` (`scripts/app-shell.js:919-1065`)
   renders a 56px header (`headerStyle`, `flexShrink: 0`, `:900-908`) and a content area
   (`contentStyle`, `flex: 1; overflowY: auto`, `:910-917`) which is the element wrapping the page's
   `Middle` at `:995-1049`. The Footer is a **third child of the same flex column**, added after that
   `div` and before the `DragDivider` (`:1054`). `.middle-column` supplies `display:flex;
   flex-direction:column; height:100%` (`styles/app-shell.css:45-54`). Nesting the Footer inside the
   `contentStyle` div still *looks* right and silently restores the scroll-to-bottom problem the whole
   spec exists to fix. Task 1's source test is the only thing standing between that and a release.
2. **The conversation overlay must not reflow the topic list.** The message log in the dock is
   `position: absolute; bottom: 100%` inside a `position: relative` dock, and is **not rendered at all**
   when there is nothing to show. If it ever becomes a normal flow child, the dock grows, the content
   area shrinks, and the list jumps — the same complaint in a new costume. `.middle-column` is already
   `position: relative; overflow: hidden` (`app-shell.css:50,53`), so the overlay is clipped to the column.
3. **The reset-effect split must keep the generation bump and the deferred-resend path.** Today one
   effect (`scripts/composites/ask-chat.js:682-698`) bumps `genRef`, clears `msgs`, and consumes
   `resendRef` / `deferredResendRef`; a second effect (`:702-707`) sends a widen that landed mid-flight.
   The split moves the day keys into effect A and `topicRowId` into effect B. **Both** bump `genRef`
   (spec §5: a late answer from the previous scope is still dropped). **Only A** touches `resendRef` /
   `deferredResendRef` — a widen only ever clears scope. Effect B must be declared *after* A so React
   runs A first, and must skip its divider when A already cleared in the same commit (a day+topic change
   arriving together), or the reader gets a divider under an empty log.
4. **(fourth, same class) Removing `AskPresence`/`hasAsk` must not leave a dangling export.**
   `scripts/pages/timeline.js` `module.exports` (`:4517-4569`) names `AskPresence`, `topicAskVisible`,
   `TopicAskButton` and `pinTopicAsk`. A deleted function still listed there is a `ReferenceError`
   *at require time*, which fails **all 17 test files that require timeline.js**, not just the Ask ones.
   `NO_TIMELINE_ASK` (`:1063-1070`) must keep exactly the key set the Provider value has, or
   `TimelineRightDetail` rendered outside a Provider reads `undefined.hasAsk`. Grep confirms no other
   page reuses `TimelineRightDetail`, so the blast radius is the tests plus a bare `/timeline` render —
   both cheap to check, neither automatic.
